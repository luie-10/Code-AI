# 후보 필터 실험 — 기각

실측: 2026-10-25 · held-out 100클래스 / 2,058쌍 / 정답 필드 489

## 결과

| 변형 | 재현율 | 정밀도 | F1 | 비고 |
|---|---|---|---|---|
| **baseline (전체 후보 + 모델)** | **74.8%** | **84.7%** | **0.795** | 현재 v3.3 |
| prefilter_code (본문 등장 후보만 + 모델) | 42.5% | 88.9% | 0.575 | **재현율 -32.3pp** |
| parser_only (본문 등장 = 전부 선택) | 54.2% | 89.8% | 0.676 | 모델 미사용 |
| hybrid (본문 등장 OR 모델 선택) | 78.1% | 84.7% | 0.813 | +3.3pp, 미미 |

## 결론: 후보 필터는 채택하지 않음

- 정밀도는 84.7% → 88.9%로 **+4.2pp** 올랐지만, 재현율이 **74.8% → 42.5%로 -32.3pp** 떨어졌습니다. F1은 0.795 → 0.575.
- 원인: 실제 사용 필드의 상당수가 메서드 본문에 **이름으로 등장하지 않습니다**(프로퍼티 경유, 콜백, 다른 메서드로 전달). 파서의 문자열 포함 검사는 이들을 전부 놓칩니다.
- hybrid는 재현율 +3.3pp지만, 이는 "본문에 등장하는 필드를 무조건 추가"한 효과이고 정밀도 이득은 없습니다(84.7% 동일). 구조 개선이라기보다 보정입니다.

## 진단과의 연결

`precision_analysis.json`에서 확인한 사실:

- 오탐 726개 중 **575개(79%)가 같은 클래스의 다른 메서드에서 사용되는 필드**입니다.
- 본문 등장 필드의 선택 정밀도는 93.2%, 미등장 필드는 **0.0%**.
- AUC 0.680, 344개 메서드 중 149개(43%)가 후보를 전부 선택.

즉 문제는 "후보가 너무 넓다"가 아니라 **"모델이 메서드 문맥을 구분하지 못한다"** 입니다. 후보를 줄이면 정밀도가 아니라 재현율이 먼저 무너집니다.
