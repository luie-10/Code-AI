# 앙상블 + 임계값 보정 — 현재 방식 강화

실측: 2026-10-26 · 추가 학습 없음 · 기존 체크포인트 재사용

## 방법

- 점수 = 각 모델의 `logit(YES) - logit(NO)` 평균
- 임계값을 **dev 82클래스**에서 0.25 간격으로 탐색, **test 100클래스**에는 그대로 적용
- test는 선택에 사용하지 않음

## 해석

- 앙상블 자체는 이득이 없었습니다(2개·3개 조합 모두 단일 모델보다 낮거나 같음).
- **이득은 임계값 보정에서 나왔습니다.** 기본 0에서 0.774이던 F1이 0.850로 상승했습니다.
- 이유: 모델 점수가 음수 쪽으로 치우쳐 있어, 0은 과소 선택입니다. dev에서 보정하면 후보를 더 넓게 잡아 재현율이 오릅니다.
- 이전 헤드라인 0.831 대비 **+0.019** (오류 16.9% → 15.0%, 약 11% 감소).

## 중요한 사실

- `ckpt_v3_5_big/last.pt`는 **step 1512**(과적합 v3.5b)입니다. 512 step 최고 모델은 저장되지 않아 **현재 디스크에 없습니다.**
- 따라서 지금 재현 가능한 최선은 **v3.7 + 임계값 보정**이며, 위 수치는 그 기준입니다.
- v3.5의 81.4/84.9/0.831은 당시 평가 기록으로만 남아 있고, 체크포인트는 소실되었습니다.

## 한계

- 임계값은 dev 82클래스에서 골랐습니다. 새 도메인에서는 재보정이 필요합니다.
- 0.25 간격의 거친 탐색이며, 더 잘게 쪼개면 dev 과적합 위험이 커집니다.
- 이득 폭은 +0.019로 작습니다. 구조적 한계(같은 클래스 내 다른 메서드 필드 오탐)는 그대로입니다.
