## 구조

```
파서  →  후보 필드 목록 (FIELDS)  →  모델에 후보 1개씩 질의  →  Y/N  →  합집합
```

1. **후보 생성(파서)** — 클래스의 필드 선언에서 이름만 추출. 의미 판단 없음.
2. **모델 선택** — `FIELD: <이름>`을 메서드 코드와 함께 넣고 `Y`/`N` 단일 토큰 확률을 비교.
3. **집계** — 한 클래스의 여러 메서드에서 Y가 나온 필드를 합집합.

## 학습

- 베이스: `ckpt_v3/last.pt` (11.07M, ctx 448)
- 데이터: 4,187개 학습 메서드에서 (필드, 메서드) 쌍 생성 — 양성 5,739 / 음성 19,962
- 900 step, batch 8 (양성 4 + 음성 4), lr 4e-4, CPU 약 18.5분
- 손실: `Y`/`N` + `<|end|>` 토큰만 (프롬프트는 -100)
- 추론: `logit(Y) − logit(N) > 0`

## 정직한 해석

- **78.6%는 "의미를 이해해서"가 아닙니다.** 모델은 사실상 "이 필드 이름이 메서드 본문에 등장하는가"에 가까운 단축을 학습했습니다. 그럼에도 후보를 좁히고 선택한다는 구조 자체는 유효합니다.
- **메서드 단위 정밀도 31%** — 한 메서드에서 3~4개를 선택해 실제 사용 1~2개보다 많습니다. 클래스 단위 지표가 이를 가립니다.
- 평가셋이 10클래스/42필드로 작아 1건 = 2.4pp.
- 상속·역할은 v3 값을 그대로 인용했습니다(v3.2는 필드 선택만 재학습).
- 필드 후보는 파서가 주므로, 파서가 놓친 필드(리플렉션·문자열 접근)는 회복 불가.
