# MiniUnityLLM v3.3 — 100클래스 평가 + 임계값 튜닝

실측: 2026-10-25 · held-out 100클래스 / 2058개 (필드, 메서드) 쌍

## 결과

| 지표 | v3.2 (10클래스) | **v3.3 (100클래스)** |
|---|---|---|
| 필드 재현율 | 78.6% | **74.7%** (369/494) |
| 필드 정밀도 | 91.7% | **84.8%** (369/435) |
| 평가 클래스 | 10 | **100** |
| 정답 필드 수 | 42 | 494 |

10클래스 결과는 운이 좋았습니다. 표본을 10배로 늘리자 재현율 -3.9pp, 정밀도 -6.9pp로 내려갔고, 이쪽이 실제 성능에 가깝습니다.

## 임계값 튜닝

학습에 쓰지 않은 train 슬라이스 220개 메서드(1,207쌍)에서 threshold를 -2.0~4.0까지 0.25 간격으로 스윕했습니다.

| 항목 | 값 |
|---|---|
| 최적 F1 | 0.446 |
| 최적 threshold | **0.00** (기존과 동일) |
| 메서드 정밀도 | 31.9% |
| 메서드 재현율 | 73.8% |

**threshold를 바꿔도 개선이 없었습니다.** 현재 `score > 0`이 이미 F1 최대점입니다. 문제는 임계값이 아니라 모델이 후보를 과선택하는 경향(FP 414) 자체입니다.

## 해석

- 100클래스에서도 **재현율 74.7%** 는 후보 선택 구조가 유효함을 보여줍니다.
- 정밀도 84.8%는 클래스 단위 합집합 기준입니다. **메서드 단위 정밀도는 31.9%** 로, 한 메서드에서 실제 사용보다 많은 필드를 고릅니다.
- 임계값으로는 해결되지 않았으므로, 다음 개선은 ① 후보 사전 필터(파서가 본문 등장 필드만 후보로) ② "본문 등장 여부" 피처를 프롬프트에 명시 ③ 7B 모델 순입니다.
