# UnityLens v4 — 파서가 추적하고, LLM이 설명한다

v3까지의 교훈은 분명했습니다. 11M from-scratch 모델은 **변수 이름을 복사하지 못한다**는 것. v4는 역할을 나눕니다.

- **파서(결정론)** — 상속, 필드, 읽기/쓰기, 호출, 외부 참조, 이슈를 확정. 식별자의 유일한 출처.
- **LLM(서술)** — 파서가 만든 팩트시트만 받아 한국어 해설 생성.
- **식별자 가드** — 모델이 백틱으로 감싼 모든 이름을 프로젝트 심볼 테이블과 대조. 목록에 없으면 `미검증`으로 표시하고 배지에 집계.

즉 LLM이 틀려도 **변수 이름은 틀릴 수 없습니다.** 가드가 잡아내고, 파서 값은 그대로 남습니다.

## 쓰는 법

1. `UnityLens.html`을 연다.
2. 기본은 **오프라인 해설**(파서 기반 규칙 + 내장 10개 샘플은 큐레이션)입니다. LLM 없이도 동작합니다.
3. 우측 상단 **LLM 오프라인** 칩 → 엔드포인트/모델 입력 → 연결 테스트 → 저장.
4. 클래스 탭의 **LLM으로 생성** → 해설 생성 + 식별자 검증 배지 표시.
5. **근거 팩트시트**를 펼치면 모델에 실제로 전달된 사실과 허용 식별자 목록을 볼 수 있습니다.

## 연결 예시 (OpenAI 호환)

| 백엔드 | 엔드포인트 | 모델 예 |
|---|---|---|
| Ollama | `http://localhost:11434/v1/chat/completions` | `qwen2.5-coder:1.5b` |
| LM Studio | `http://localhost:1234/v1/chat/completions` | 로드한 모델명 |
| OpenAI | `https://api.openai.com/v1/chat/completions` | `gpt-4o-mini` |

```bash
ollama run qwen2.5-coder:1.5b
```

API 키는 탭 메모리에만 보관되고 저장되지 않습니다. 코드는 브라우저에서 파서로 처리되며, LLM을 연결한 경우에만 **팩트시트(코드 원문 아님)** 가 해당 엔드포인트로 전송됩니다.

## 한계

- LLM 해설은 여전히 문장 수준에서 틀릴 수 있습니다(인과 추론, 생략). 이름만 보증됩니다.
- 오프라인 해설은 템플릿 기반이라 문장이 반복됩니다.
- `#if`, 리플렉션, UnityEvent 간접 호출은 파서도 추적하지 못합니다.
